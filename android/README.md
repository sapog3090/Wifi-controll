# WifiCtl — Android-приложение

Нативное Android-приложение (Kotlin + Jetpack Compose) с двумя режимами в одном
APK:

- **Агент** — foreground-сервис с постоянным уведомлением (как у Shizuku). Держит
  TLS-сервер, объявляет устройство в сети по mDNS и показывает **QR сопряжения**.
- **Контроллер** — сканирует QR, сохраняет устройства, находит их в WiFi по mDNS,
  даёт кнопки макросов и (если разрешено) ввод произвольных команд.

Протокол (построчный JSON поверх TLS) совместим с Python-реализацией из корня
репозитория.

> ⚠️ Только с согласия владельца. Агент включается вручную и виден в уведомлениях;
> подключиться можно лишь с QR/токеном, который показывает сам владелец телефона.

## Как пользоваться

На телефоне, которым будут управлять (например, телефон подруги — с её ведома):
вкладка **Агент** → «Включить агент» → показать QR.

На своём телефоне: вкладка **Контроллер** → «Сканировать QR» → устройство
сохраняется → «Подключиться» → жать кнопки макросов (`root`, `net`, `battery`,
`full`). Дальше оно находится в сети автоматически (mDNS), QR больше не нужен.

Команды выполняются от имени приложения (без root) — этого хватает для
информационных макросов.

## Сборка APK

Локально: открыть папку `android/` в Android Studio и запустить сборку, либо

```bash
cd android && gradle :app:assembleDebug
```

В CI: при пуше изменений в `android/**` воркфлоу
[`.github/workflows/android.yml`](../.github/workflows/android.yml) собирает
debug-APK и кладёт его в артефакты запуска (вкладка **Actions** → артефакт
`wifictl-debug-apk`).

## Стек

Kotlin 1.9, AGP 8.5, compileSdk 34, minSdk 26, Jetpack Compose (Material3),
kotlinx.serialization, BouncyCastle (генерация self-signed сертификата), ZXing
(QR), Android NSD (mDNS), TLS через `javax.net.ssl`.
