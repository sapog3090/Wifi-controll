# wifictl

Управление **своими или авторизованными** устройствами по WiFi (локальной сети)
из терминала: пишешь ключевое слово — на устройстве выполняется заранее
заданный набор команд (макрос). Опционально — произвольные команды.

> ⚠️ **Только с разрешения.** Инструмент предназначен для устройств, которыми вы
> владеете, или на управление которыми у вас есть явное разрешение владельца.
> Это не средство несанкционированного доступа.

## Как устроено

Две части, общаются по WebSocket поверх TLS в пределах одной WiFi-сети:

- **Агент** (`wifictl agent`) — запускается на целевом устройстве (Linux/ПК или
  телефон в Termux). Слушает сеть, проверяет токен, разворачивает макросы,
  выполняет команды, стримит вывод обратно и пишет аудит-лог.
- **Клиент** (`wifictl connect`) — интерактивный REPL на твоей машине или
  телефоне. Вводишь слово макроса → оно уходит агенту → видишь вывод.

Телефон может быть и клиентом, и агентом — всё по WiFi.

## Установка

```bash
pip install -e .          # Python 3.10+
```

На Android — в [Termux](https://termux.dev/): `pkg install python`, затем `pip install -e .`.

## Быстрый старт

**На устройстве-цели** (где будут выполняться команды):

```bash
wifictl init                       # создаст сертификат, токен и config/
wifictl agent --config config/agent.yaml
```

`init` напечатает готовую строку подключения с `host`, `port`, `token` и
`fingerprint` (SHA-256 отпечаток сертификата).

**На клиенте** (откуда вводишь команды):

```bash
wifictl connect 192.168.1.50:8765 --token <ТОКЕН> --fingerprint <ОТПЕЧАТОК>
```

В REPL:

```
wifictl> root            # выполнить макрос
wifictl> deploy dir=/srv/app   # макрос с параметром
wifictl> !uptime         # произвольная команда (если разрешено на агенте)
wifictl> :macros         # список макросов
wifictl> :help           # справка
wifictl> :quit           # выход
```

## Макросы

Файл `config/macros.yaml`. Ключевое слово → список команд. `@имя` включает другой
макрос, `{param}` подставляется из параметров:

```yaml
macros:
  root:
    description: "Снимок состояния системы"
    commands: ["whoami", "uptime", "df -h"]
  full:
    commands: ["@root", "free -h"]
  deploy:
    params: [dir]
    commands: ["cd {dir} && git pull --ff-only"]
```

Команды в макросе выполняются по порядку; последовательность прерывается на
первой команде с ненулевым кодом возврата.

## Безопасность

- **TLS** обязателен; `init` генерирует self-signed сертификат, клиент пиннит его
  отпечаток (trust-on-first-use) — защита от подмены агента.
- **Токен** — pre-shared, сравнивается в постоянное время.
- **Произвольные команды** выключены по умолчанию (`allow_arbitrary: false`).
  Включайте осознанно.
- **allow/deny-списки** бинарей (`allow_binaries`, `deny_binaries`) ограничивают,
  что вообще можно запустить; deny действует даже при `allow_arbitrary: true`.
- **Аудит-лог** (`audit.log`, JSON-lines) фиксирует каждую команду: время, адрес
  клиента, команду, код возврата, статус (`executed`/`denied`/`error`).
- **Таймаут** на каждую команду (`command_timeout`).

Файлы с секретами (`agent.yaml`, `*.pem`, `*.key`, `audit.log`) — в `.gitignore`,
не коммитятся. Агент биндится на `0.0.0.0`; ограничьте доступ файрволом до
доверенной сети.

## Конфигурация агента

См. `config/agent.example.yaml`. Ключевые поля: `host`, `port`, `token`,
`cert_path`, `key_path`, `macros_path`, `audit_log`, `allow_arbitrary`,
`allow_binaries`, `deny_binaries`, `command_timeout`. Относительные пути в конфиге
разрешаются относительно каталога самого конфига.

## Ограничения

- iOS: полноценного агента нет (песочница); как клиент — ограниченно через
  a-Shell/iSH.
- Рассчитано на доверенную локальную сеть, а не на доступ из интернета.
